# Database

Supabase Postgres 17. Everything is defined in `supabase/migrations` and applied in order:

| Migration | Contents |
| --- | --- |
| `…000100_core_schema.sql` | Enums, tables, generated columns, maintenance triggers, `inventory` view |
| `…000200_functions.sql` | Auth helpers, catalogue views and search, order/payment/stock functions, grants |
| `…000300_rls.sql` | Row Level Security policies and column grants |
| `…000400_storage.sql` | Storage buckets and their policies |
| `…000500_reference_data.sql` | Role permissions, default settings, homepage sections, delivery zones |
| `…000600_content_pages.sql` | Draft content pages, reporting views |

`supabase/seed.sql` (demo catalogue, demo users, sample orders and reviews) is for local
development only. It is generated by `npm run db:seed:generate` from `scripts/seed/*`.

Change the schema by adding a new migration (`npx supabase migration new <name>`), then run
`npx supabase db reset` locally, `npm run db:types` to refresh `src/types/database.ts`, and
`npm run test:db`.

## Tables

**People**

- `profiles`: one row per auth user (created by the `handle_new_user` trigger): name, phone,
  `avatar_url` (their uploaded picture, kept in the public `avatars` bucket under a folder named
  after their user id; without one the store shows their Google picture),
  `role` (`user_role` enum), active flag. `protect_profile_role` stops users changing their own role.
- `role_permissions`: (`role`, `permission`) pairs. See [ADMIN.md](ADMIN.md) for the list.
- `addresses`: saved delivery addresses (county, town, area, landmark).

**Catalogue**

- `brands`, `categories` (tree via `parent_id`), `printer_models` (brand, model number, series).
- `products`: name, slug, SKU, brand, category, `product_type`, price, `compare_at_price`,
  `discount_percent`, `stock_quantity`, `reserved_quantity`, generated `available_quantity`,
  low-stock threshold, `status` (`draft` / `active` / `archived`), flags (featured, best seller,
  new), specs JSON, SEO fields, rating aggregates, and `search_text` / `search_vector` for search.
- `product_costs`: cost price, kept apart so only staff with `products.manage` can read it.
- `product_variants`: optional variants (e.g. colour or capacity) with their own SKU, price and stock.
- `product_images`: ordered images with alt text.
- `product_compatibility`: product ↔ printer model, used by the parts finder and product pages.
- `reviews`: rating and text, moderated (`pending` / `approved` / `rejected`); approved reviews
  update the product's rating via trigger.

**Orders and payments**

- `orders`: number (`CISS-YYYYMMDD-NNNN`), customer or guest contact, delivery address,
  delivery zone, money columns (subtotal, discount, delivery fee, total), `payment_method`,
  `payment_status`, `order_status`, `stock_state`, `reservation_expires_at`, guest access token.
- `order_items`: snapshot of name, SKU, unit price and quantity at the time of purchase.
- `order_status_history`: every status change with who made it and a note.
- `payments`: one row per payment attempt: provider, amount, phone, `merchant_request_id`,
  `checkout_request_id`, `transaction_reference` (M-Pesa receipt, unique), status, result code,
  raw callback.
- `coupons`, `coupon_usage`; `delivery_zones` (counties, fee, estimate).
- `carts` / `cart_items`, `wishlists` / `wishlist_items` for signed-in users.
- `inventory_transactions`: every stock movement with reason, quantity change, actor, order.

**Content and operations**

- `settings`: key → JSON (`business`, `payment_methods`, `checkout`, `seo`, `notifications`,
  `page:<slug>`). `is_public` controls whether the anonymous role can read a key.
- `homepage_sections`, `homepage_banners`.
- `support_requests` (contact and part-request forms), `notifications` (staff inbox).
- `audit_logs`: staff actions. `rate_limits`: counters used by `check_rate_limit()`.

## Order and payment states

```
order_status:   PENDING ─┬─► PAID ─► PROCESSING ─► READY_FOR_DISPATCH ─► SHIPPED ─► DELIVERED
                         │     (cash on delivery / bank transfer: PENDING ─► PROCESSING / PAID)
PAYMENT_PENDING ─────────┴─► (confirm_payment) PAID          any active state ─► CANCELLED / REFUNDED
                         └─► FAILED / CANCELLED when the payment window expires
payment_status: PENDING, PROCESSING, PAID, FAILED, CANCELLED, REFUNDED
stock_state:    reserved ─► deducted (paid) │ released (expired/cancelled) │ restocked (refund/cancel after deduction)
```

The exact allowed transitions are in `update_order_status()`; online payments can only be marked
paid by `confirm_payment()`, never by a staff status change.

## Functions

All are `SECURITY DEFINER` with a fixed `search_path`, and `EXECUTE` is granted only to the
roles that need them.

| Function | Called by | Does |
| --- | --- | --- |
| `place_order(order jsonb)` | checkout action (service role) | Prices every line from `products` (ignoring any client price), applies coupon and delivery fee, locks rows, reserves stock, writes order + items + history, returns number and token. Raises `EMPTY_CART`, `INVALID_QUANTITY`, `INSUFFICIENT_STOCK`, `COUPON_INVALID`, `COUPON_EXHAUSTED`, `COUPON_CUSTOMER_LIMIT`. |
| `confirm_payment(payment_id, receipt, amount, raw)` | M-Pesa callback / STK query | Idempotent. If the amount is below the order total it fails the attempt, alerts staff and returns `amount_mismatch`. Otherwise marks payment and order paid, deducts stock (flagging a `shortage` if a late payment arrives after the reservation was released), records history and returns `confirmed`; a repeat returns `already_paid`. |
| `fail_payment(payment_id, code, description, raw)` | callback / STK query / timeout | Marks the attempt failed; the order stays payable until it expires. |
| `expire_stale_orders()` | cron, order page polling | Cancels unpaid orders past `reservation_expires_at` and releases their stock. |
| `update_order_status(order_id, status, note)` | admin | Enforces transitions and permissions (`orders.manage`, `orders.refund`), restocks on cancel/refund after deduction. |
| `adjust_stock(product_id, variant_id, change, reason, note)` | admin | Stock adjustments with a reason; writes `inventory_transactions`; refuses to go below the reserved quantity (`STOCK_BELOW_RESERVED`). |
| `catalog_search(query, category, brands, …, sort, page)` | search, listings | Prefix full-text search plus trigram match on SKU, model and part numbers, with filters and a total count. |
| `admin_dashboard_stats(days)` | admin dashboard | Revenue, orders by status, top products, low stock for the last N days. |
| `check_rate_limit(key, limit, window)` | server actions | Fixed-window counter. |
| `has_permission(permission)`, `is_staff()`, `is_service_role()` | RLS policies | Authorisation helpers. `is_service_role()` checks the JWT role, not `current_user`, so it is correct inside `SECURITY DEFINER` functions. |

Views: `product_cards` (listing data with availability across variants), `category_product_counts`,
`product_counts_by_category`, `product_counts_by_brand`, `compatibility_counts`, `inventory`,
`inventory_totals`, `customers` (staff only).

## Row Level Security summary

| Data | Anonymous | Customer | Staff |
| --- | --- | --- | --- |
| Active products, categories, brands, models, images, compatibility | read | read | read + write with `products.manage` / `catalog.manage` |
| Draft/archived products, `product_costs` | – | – | `products.manage` |
| Approved reviews | read | read; write own (pending) | moderate with `reviews.moderate` |
| Public settings, homepage, delivery zones | read | read | write with `settings.manage` / `content.manage` |
| Orders, items, history, payments | – | own (read) | read with `orders.manage` or `customers.view`; only `admin_notes` is directly writable |
| Profiles, addresses, carts, wishlists | – | own | `customers.view` (read) |
| Support requests | via server action | via server action; read own | `support.manage` |
| Audit logs | – | – | read with `reports.view` or `admins.manage` |

Orders are created only through `place_order()`; guests read their order through the server
(service role) after the order token is checked.

## Storage buckets

`product-images` (5 MB), `brand-logos` (2 MB, SVG allowed), `category-images` (5 MB),
`banners` (8 MB), `review-images` (5 MB) are publicly readable; uploads require the matching
staff permission (customers may upload review images into their own folder).
`support-attachments` (8 MB, images and PDF) is private.

## Tests

- `tests/db/order_lifecycle.sql`: place order, reserve, confirm (and confirm again), amount
  mismatch, expiry and release, transitions, refunds and restock.
- `tests/db/rls.sql`: impersonates anon, customers and staff roles and checks what each can read and write.

Run both with `npm run test:db` (it resets the local database first).
